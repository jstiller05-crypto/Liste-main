SSH

SSH (Secure Shell, Port 22) ermöglicht verschlüsselten Fernzugriff auf einen anderen Rechner – meist auf ein Terminal, um dort Befehle auszuführen, als säße man direkt davor.

FTP / SFTP

FTP (File Transfer Protocol, Port 20/21) überträgt Dateien zwischen zwei Rechnern – unverschlüsselt und darum heute veraltet. SFTP (SSH File Transfer Protocol) macht dasselbe, aber verschlüsselt über SSH (Port 22) – die heute übliche Wahl.

ICMP (ping)

ICMP (Internet Control Message Protocol) überträgt Status- und Fehlermeldungen zwischen Netzwerkgeräten – anders als TCP/UDP transportiert es keine „Nutzdaten“ für Anwendungen. Das bekannte Werkzeug ping nutzt ICMP, um zu prüfen, ob ein Ziel erreichbar ist, und misst dabei genau die Latenz (siehe Netzwerk-Grundlagen im Spicker).

ARP

ARP (Address Resolution Protocol) übersetzt innerhalb eines lokalen Netzes eine IP-Adresse in die passende MAC-Adresse (siehe Netzwerk-Geräte im Spicker) – nötig, weil Switches Pakete anhand der MAC-Adresse weiterleiten, nicht anhand der IP.

WebSocket

Ein WebSocket baut – anders als klassisches HTTP mit jeweils neuer kurzer Verbindung pro Anfrage – EINE dauerhafte Verbindung auf, über die Browser UND Server jederzeit in BEIDE Richtungen Nachrichten schicken können. Praktisch für Echtzeit-Anwendungen wie Chats oder Live-Updates, bei denen der Server auch von sich aus etwas mitteilen muss.

Tipps & typische Fehler

  • SFTP hat trotz des Namens NICHTS mit FTPS (FTP über TLS) zu tun – zwei unterschiedliche Wege, Dateiübertragung abzusichern.
  • Ein blockiertes ICMP (z. B. per Firewall) lässt ein Gerät für ping „unerreichbar“ wirken, obwohl andere Dienste (z. B. eine Webseite darauf) einwandfrei funktionieren.
  • WebSocket startet technisch als normale HTTP-Anfrage, die dann auf eine dauerhafte Verbindung „hochgestuft“ wird (Upgrade) – kein komplett eigenständiges, unabhängiges Protokoll von Grund auf.
