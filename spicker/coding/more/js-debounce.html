Debounce & Throttle

Funktionen bremsen, die sonst viel zu oft aufgerufen würden – z. B. bei Suche, Scrollen oder Fenstergröße.

Das Problem

Das Event input feuert bei jedem Tastendruck. Startet jede Eingabe eine teure Suche oder eine Server-Anfrage, läuft beim Wort „Tabelle“ siebenmal dieselbe Arbeit.

Debounce – erst wenn Ruhe ist

function debounce(fn, delay = 300) {
  let timeoutId;
  return (...args) => {
    clearTimeout(timeoutId);                          // alten Timer verwerfen
    timeoutId = setTimeout(() => fn(...args), delay); // neuen starten
  };
}

const search = debounce((text) => {
  console.log("[search] suche nach:", text);
}, 300);

input.addEventListener("input", () => search(input.value));

Erst wenn 300 ms lang nichts getippt wurde, läuft die Suche – genau einmal.

Aufrufe: 0 (input) · 0 (debounced)

Throttle – höchstens alle X ms

function throttle(fn, interval = 200) {
  let lastRun = 0;
  return (...args) => {
    const now = Date.now();
    if (now - lastRun >= interval) {
      lastRun = now;
      fn(...args);
    }
  };
}

window.addEventListener("scroll", throttle(() => {
  console.log("[scroll]", window.scrollY);
}, 200));

Welches wann?

MusterVerhaltenTypisch für
DebounceWartet, bis die Ereignisse aufhören, dann einmalSuchfeld, Autosave, Fenstergröße
ThrottleFührt regelmäßig aus, solange Ereignisse kommenScrollen, Mausbewegung, Spiel-Eingaben

Tipps & typische Fehler

  • Beide Funktionen nutzen eine Closure, um sich den Timer bzw. den letzten Zeitpunkt zu merken.
  • Für kleine Listen (wie ein paar hundert Einträge) ist Filtern ohne Debounce meist schnell genug – bei Server-Anfragen ist Debounce Pflicht.
