Fehler & Exceptions

Fehler mit try/except abfangen, mit raise selbst auslösen, eigene Exceptions bauen – und einen Traceback richtig lesen.

Was ist das?

Geht zur Laufzeit etwas schief – Datei fehlt, Text ist keine Zahl, Division durch null –, löst Python eine Exception (Ausnahme) aus. Fängt niemand sie ab, bricht das Programm ab und zeigt einen Traceback. Mit try/except reagiert man stattdessen gezielt darauf.

try / except / else / finally

# safe_input.py
def read_number(text):
    try:
        number = int(text)                  # kann ValueError auslösen
    except ValueError:
        print(f"[warn] '{text}' ist keine ganze Zahl")
        return None
    else:
        print("[ok] Umwandlung hat geklappt")   # läuft nur OHNE Fehler
        return number
    finally:
        print("[info] fertig mit", repr(text))  # läuft IMMER – mit und ohne Fehler

print(read_number("42"))
print(read_number("abc"))
python safe_input.py

Mehrere Fehlerarten

# divide.py
def divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        print("[warn] Division durch null")
    except TypeError as error:              # "as error" gibt Zugriff auf die Meldung
        print("[warn] falscher Typ:", error)
    return None

print(divide(10, 2))
print(divide(10, 0))
print(divide("10", 2))

# Mehrere Arten gleich behandeln: als Tupel
try:
    value = int(input("Zahl: "))
    print(100 / value)
except (ValueError, ZeroDivisionError) as error:
    print("[warn] ungültige Eingabe:", error)
python divide.py

raise – selbst einen Fehler auslösen

# validate.py
def set_volume(level):
    if not isinstance(level, (int, float)):
        raise TypeError("level muss eine Zahl sein")
    if not 0 <= level <= 100:
        raise ValueError(f"level muss zwischen 0 und 100 liegen, nicht {level}")
    print("Lautstärke:", level)

set_volume(40)

try:
    set_volume(150)
except ValueError as error:
    print("[error]", error)
python validate.py

Eigene Exceptions

Eine eigene Exception ist eine Klasse, die von Exception erbt. So kann der Aufrufer genau diesen Fehler abfangen und alle anderen durchlassen.

# shop.py
class InsufficientFundsError(Exception):
    """Wird ausgelöst, wenn das Guthaben nicht reicht."""

    def __init__(self, balance, price):
        super().__init__(f"Guthaben {balance} € reicht nicht für {price} €")
        self.missing = price - balance      # Zusatz-Info für den Aufrufer


def buy(balance, price):
    if price > balance:
        raise InsufficientFundsError(balance, price)
    return balance - price


try:
    print(buy(50, 20))                      # 30
    print(buy(30, 99))                      # löst den Fehler aus
except InsufficientFundsError as error:
    print("[error]", error)
    print("Es fehlen", error.missing, "€")
python shop.py

Traceback lesen

Ein Traceback sieht erschreckend aus, ist aber eine genaue Wegbeschreibung. Von unten nach oben lesen: Die letzte Zeile sagt, was schiefging, die Zeilen darüber, wo.

# crash.py
def load_score(data, name):
    return data[name]                       # Zeile 3

def show(name):
    scores = {"Anna": 150}
    print(load_score(scores, name))         # Zeile 7

show("Max")                                 # Zeile 9
python crash.py
Traceback (most recent call last):
  File "/home/user/crash.py", line 9, in <module>        ← 3) hier begann es
    show("Max")                                 # Zeile 9
    ~~~~^^^^^^^
  File "/home/user/crash.py", line 7, in show            ← 2) show rief load_score auf
    print(load_score(scores, name))         # Zeile 7
          ~~~~~~~~~~^^^^^^^^^^^^^^
  File "/home/user/crash.py", line 3, in load_score      ← 1) hier knallte es
    return data[name]                       # Zeile 3
           ~~~~^^^^^^
KeyError: 'Max'                                          ← WAS: Schlüssel 'Max' fehlt

Die Zeichen ~~~^^^ unter jeder Zeile markieren die genaue Stelle im Ausdruck. Die Pfeile ← rechts sind hier nur Erklärung – die druckt Python nicht.

  1. Letzte Zeile: Fehlertyp und Meldung (KeyError: 'Max').
  2. Darüber: die Zeile, in der es passiert ist (line 3).
  3. Weiter oben: der Weg dorthin – wer hat wen aufgerufen.

Tipps & typische Fehler

  • Kein nacktes except: – es fängt auch Tippfehler (NameError) und Strg+C ab und versteckt so echte Fehler. Immer die erwartete Art nennen.
  • Fehler nicht stumm verschlucken (except ValueError: pass). Mindestens eine Meldung ausgeben, sonst sucht man später ewig.
  • Nur den Code in try stellen, der wirklich fehlschlagen kann – nicht die halbe Funktion.
  • try/except ist für erwartbare Probleme (Eingabe, Datei, Netzwerk). Programmierfehler behebt man im Code, nicht mit except.
  • In einem except-Block wirft ein einzelnes raise denselben Fehler weiter – nützlich, wenn man nur loggen will.
  • Für Dateien with statt finally: file.close() benutzen, siehe Dateien.
