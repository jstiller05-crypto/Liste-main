fetch & APIs

Daten von Servern laden und senden – mit Ladezustand und sauberer Fehlerbehandlung.

GET – Daten laden

async function loadUsers() {
  const response = await fetch("https://jsonplaceholder.typicode.com/users");

  if (!response.ok) {                              // fetch wirft bei 404/500 KEINEN Fehler!
    throw new Error(`HTTP ${response.status}`);
  }
  return response.json();                          // Antwort als JSON lesen
}

try {
  const users = await loadUsers();
  console.table(users);
} catch (error) {
  console.error("[fetch] Laden fehlgeschlagen:", error.message);
}

POST – Daten senden

const response = await fetch("/api/tasks", {

Ladezustand anzeigen

const list = document.getElementById("userList");
const status = document.getElementById("status");

async function showUsers() {
  status.textContent = "Lädt …";
  try {
    const users = await loadUsers();
    list.innerHTML = "";
    users.forEach(user => {
      const li = document.createElement("li");
      li.textContent = user.name;               // textContent: sicher
      list.appendChild(li);
    });
    status.textContent = "";
  } catch {
    status.textContent = "Konnte nicht geladen werden. Bitte später erneut versuchen.";
  }
}

Wichtige Begriffe

BegriffBedeutung
APISchnittstelle, über die ein Server Daten anbietet (meist als JSON)
EndpointEine Adresse der API, z. B. /api/users
Statuscode200 OK, 201 erstellt, 400 falsche Anfrage, 401 nicht angemeldet, 404 nicht gefunden, 500 Serverfehler
CORSSicherheitsregel: Ein Browser darf Daten von einer anderen Domain nur laden, wenn deren Server es erlaubt
Query-Parameter?search=html&page=2 – mit new URLSearchParams({ search, page }) bauen

Abbrechen & Zeitlimit

// Nach 5 Sekunden abbrechen
const response = await fetch(url, { signal: AbortSignal.timeout(5000) });

Tipps & typische Fehler

  • response.ok immer prüfen – fetch scheitert nur bei Netzwerkfehlern, nicht bei 404.
  • fetch funktioniert nicht aus Dateien, die per Doppelklick (file://) geöffnet sind – einen lokalen Server wie „Live Server“ in VS Code nutzen.
  • API-Schlüssel gehören nie in Frontend-Code – den kann jeder im Browser lesen.
