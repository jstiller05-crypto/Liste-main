Scope, Closures, Hoisting & this

Wo eine Variable sichtbar ist, warum Funktionen sich Werte „merken“ – und was this gerade bedeutet.

Scope – Sichtbarkeit

const globalValue = "überall sichtbar";

function outer() {
  const outerValue = "in outer";

  if (true) {
    const blockValue = "nur in diesem Block";   // let/const: Block-Scope
    var oldStyle = "ganze Funktion";            // var: Funktions-Scope (verwirrend)
    console.log(globalValue, outerValue, blockValue);
  }

  console.log(oldStyle);        // funktioniert (var)
  // console.log(blockValue);   // ReferenceError
}

Closures

Eine Funktion „merkt“ sich die Variablen der Umgebung, in der sie erzeugt wurde – auch wenn diese Umgebung längst vorbei ist.

function createCounter() {
  let count = 0;                 // von außen nicht erreichbar
  return {
    increase: () => ++count,
    reset: () => { count = 0; }
  };
}

const counter = createCounter();
counter.increase();   // 1
counter.increase();   // 2
// count selbst ist privat – nur über die Funktionen änderbar

Closures stecken hinter vielen Mustern: private Daten, Debounce, Event-Handler, die sich Werte merken.

Hoisting

sayHello();                  // funktioniert! Funktionsdeklarationen werden "nach oben gezogen"
function sayHello() { console.log("Hallo"); }

console.log(a);              // undefined (var wird hochgezogen, aber ohne Wert)
var a = 5;

// console.log(b);           // ReferenceError – let/const erst ab ihrer Zeile nutzbar
let b = 5;

this

Aufrufthis ist …
obj.methode()obj
Normale Funktion f()undefined (im strict mode / Modulen)
Pfeilfunktiondas this der Umgebung, in der sie steht
Event-Handler mit functiondas Element, an dem der Listener hängt
new Klasse()das neue Objekt
 
class Timer {
  seconds = 0;

  start() {
    // FALSCH: setInterval(function () { this.seconds++; }, 1000);  → this ist nicht der Timer
    setInterval(() => {            // Pfeilfunktion übernimmt this von start()
      this.seconds++;
      console.log(this.seconds);
    }, 1000);
  }
}

Tipps & typische Fehler

  • Immer let/const, nie var – dann gibt es keine Hoisting-Überraschungen.
  • Verlierst du this in einem Callback: Pfeilfunktion verwenden oder .bind(this).
  • Eine Schleife mit let i erzeugt für jeden Durchlauf ein eigenes i – mit var teilen sich alle Callbacks dasselbe.
