CPU / Prozessor

Die CPU (Central Processing Unit, Prozessor) führt die eigentlichen Berechnungen aus. Im Kern läuft dabei immer derselbe Zyklus: Fetch (Befehl aus dem Speicher holen), Decode (Befehl entschlüsseln) und Execute (Befehl ausführen) – und dann von vorn.

Kern & Thread

Ein Kern (Core) ist eine eigenständige Recheneinheit innerhalb der CPU – moderne Prozessoren haben meist mehrere Kerne, die unabhängig voneinander arbeiten können. Ein Thread ist ein Ausführungsstrang: Mit „Hyper-Threading“/SMT kann EIN physischer Kern wie zwei logische Kerne wirken, indem er sich bestimmte interne Ressourcen teilt – das bringt etwas, ist aber NICHT dieselbe Leistung wie zwei echte physische Kerne.

Taktfrequenz (GHz)

Die Taktfrequenz gibt an, wie viele Grundzyklen die CPU pro Sekunde durchläuft – 1 GHz = eine Milliarde Zyklen pro Sekunde. Mehr GHz bedeutet NICHT automatisch mehr Leistung: Wie viel eine CPU pro Takt tatsächlich erledigt (IPC, „Instructions per Cycle“), hängt stark von der Architektur ab. Taktfrequenzen sind darum nur innerhalb derselben CPU-Generation gut vergleichbar.

Cache (L1/L2/L3)

Der Cache ist ein kleiner, sehr schneller Zwischenspeicher direkt am Prozessor, der häufig gebrauchte Daten und Befehle vorhält – damit die CPU nicht bei jedem Zugriff auf das deutlich langsamere RAM warten muss.

Register

Register sind winzige Speicherzellen direkt in der CPU – schneller als jeder Cache, aber auch extrem knapp (meist nur eine Handvoll). In ihnen liegen die Werte, mit denen die CPU GERADE JETZT rechnet.

Befehlssatz (x86-64 vs. ARM)

Der Befehlssatz (Instruction Set Architecture, ISA) legt fest, welche Maschinenbefehle eine CPU überhaupt versteht. Programme für einen Befehlssatz laufen ohne Übersetzung/Emulation NICHT auf einem anderen.

BefehlssatzTypisch verbaut in
x86-64die meisten Desktop-PCs, Laptops, Server (Intel, AMD)
ARMSmartphones, viele Laptops (z. B. Apple Silicon) – sehr energieeffizient

32 vs. 64 Bit

„32-Bit“ bzw. „64-Bit“ beschreibt u. a. die Breite der Register und Adressen, mit denen eine CPU arbeitet. Eine 32-Bit-Adresse kann maximal 2³² Byte = 4 GiB Arbeitsspeicher ansprechen – 64-Bit-Systeme adressieren theoretisch enorm viel mehr und sind heute praktisch Standard.

Maschinencode & Assembler

Maschinencode sind die rohen Bytes, die die CPU direkt ausführt. Assembler ist eine für Menschen lesbare 1:1-Textdarstellung davon – ein Befehl im Assembler entspricht (fast) genau einem Maschinenbefehl, ganz anders als z. B. eine Zeile C++ oder JavaScript.

; Assembler (vereinfacht, x86-artig)
MOV AX, 5     ; Register AX = 5
ADD AX, 3     ; AX = AX + 3  (jetzt 8)

Logikgatter

Ganz unten besteht eine CPU aus Millionen winziger Logikgatter – elektronische Bauteile, die AND, OR, XOR und NOT auf einzelne Bits anwenden (siehe Bitoperatoren im Daten-Teil des Spickers). Aus genau diesen einfachen Bausteinen wird Schicht für Schicht alles zusammengesetzt, bis am Ende eine komplette CPU entsteht.

Tipps & typische Fehler

  • „Mehr Kerne“ hilft nur, wenn ein Programm die Arbeit auch wirklich auf mehrere Kerne aufteilen kann – viele Alltagsaufgaben laufen weiterhin größtenteils auf einem Kern.
  • GHz-Zahlen verschiedener CPU-Generationen oder -Hersteller direkt zu vergleichen, führt leicht in die Irre – die Architektur zählt mindestens genauso viel.
  • „64-Bit-System“ und „64-Bit-Programm“ sind zwei verschiedene Dinge: Ein 64-Bit-Betriebssystem kann durchaus noch 32-Bit-Programme ausführen.
