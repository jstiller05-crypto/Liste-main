Virtuelle Maschine

Eine virtuelle Maschine (VM) ist Software, die einen kompletten Computer samt eigener (virtueller) Hardware simuliert. Darin läuft ein VOLLSTÄNDIGES, eigenes Betriebssystem – isoliert vom Host-System, als wäre es ein ganz eigener Rechner.

Container / Docker

Ein Container ist leichtgewichtiger als eine VM: Container teilen sich den Kernel des Host-Betriebssystems, isolieren aber Prozesse, Dateisystem und Netzwerk voneinander. Dadurch brauchen sie KEIN eigenes komplettes Betriebssystem, starten viel schneller und verbrauchen weniger Ressourcen als eine VM. Docker ist das verbreitetste Werkzeug dafür.

WSL

WSL (Windows Subsystem for Linux) lässt eine echte Linux-Umgebung direkt unter Windows laufen, ohne eine separate VM von Hand einzurichten. Die aktuelle Version WSL2 nutzt dafür intern eine schlanke, schnell startende virtuelle Maschine – praktisch für alle, die unter Windows mit Linux-Werkzeugen entwickeln wollen.

Tipps & typische Fehler

  • „Virtualisierung“ und „Emulation“ werden oft verwechselt: Eine VM läuft meist auf DERSELBEN Prozessor-Architektur (schnell), ein Emulator bildet eine ANDERE Architektur komplett in Software nach (deutlich langsamer).
  • Container isolieren Prozesse und Dateien, aber NICHT die Hardware wie eine VM – ein Kernel-Sicherheitsproblem im Host kann theoretisch alle Container darauf betreffen.
  • WSL2 ist KEIN „Linux-Modus“ von Windows, sondern technisch eine eigene, nur sehr eng integrierte virtuelle Maschine.
