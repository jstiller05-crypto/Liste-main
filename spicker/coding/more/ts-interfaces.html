Interfaces & Objekttypen

Beschreiben, wie ein Objekt aussehen muss – welche Eigenschaften es hat und welche Typen sie haben.

Ein Objekt beschreiben

interface User {
  name: string;
  email: string;
  age: number;
}

const user: User = {
  name: "Max Mustermann",
  email: "max@example.com",
  age: 30,
};

// const broken: User = { name: "Erika" };
// Fehler: email und age fehlen

Das Interface selbst erzeugt keinen Code – es ist nur ein Bauplan für die Prüfung und verschwindet beim Übersetzen.

Optional und readonly

interface Product {
  readonly id: number;    // darf nach dem Anlegen nicht geändert werden
  title: string;
  price: number;
  description?: string;   // optional: darf fehlen
}

const lamp: Product = { id: 1, title: "Lampe", price: 29.9 };
lamp.price = 24.9;   // ok
lamp.id = 2;         // Fehler: id ist readonly

// Optionale Eigenschaften können undefined sein → vorsichtig benutzen
console.log(lamp.description?.toUpperCase() ?? "keine Beschreibung");

Verschachtelte Objekte und Arrays

interface Address {
  street: string;
  city: string;
}

interface Customer {
  name: string;
  address: Address;
  tags: string[];
}

const customers: Customer[] = [
  { name: "Max", address: { street: "Musterweg 1", city: "Musterstadt" }, tags: ["neu"] },
];

Funktionen mit Objekt-Parametern

function showUser(user: User): void {
  console.log(`${user.name} <${user.email}>`);
}

// Destrukturierung mit Typ
function showPrice({ title, price }: Product): string {
  return `${title}: ${price.toFixed(2)} €`;
}

Interfaces erweitern

interface Animal {
  name: string;
}

interface Dog extends Animal {
  breed: string;
}

const pet: Dog = { name: "Bello", breed: "Dackel" };

Funktionstypen

// Typ für eine Funktion: bekommt zwei Zahlen, gibt eine Zahl zurück
type Calculator = (a: number, b: number) => number;

const add: Calculator = (a, b) => a + b;        // a und b sind automatisch number
const multiply: Calculator = (a, b) => a * b;

// Callback als Parameter
function onClick(handler: (event: MouseEvent) => void) {
  document.addEventListener("click", handler);
}

interface oder type?

interfacetype
Objekte beschreibenjaja
Union (A | B)neinja
Erweiternextends& (Schnittmenge)

type Point = { x: number; y: number };
type Point3D = Point & { z: number };   // Point plus z

Für Anfänger: Objekte mit interface, alles andere (Unions, Funktionstypen) mit type. Beides ist richtig.

Objekte mit beliebigen Schlüsseln

// Record<Schlüssel, Wert>
const prices: Record<string, number> = {
  apfel: 0.5,
  birne: 0.7,
};

type Theme = "hell" | "dunkel";
const colors: Record<Theme, string> = {
  hell: "#ffffff",
  dunkel: "#1e1e1e",
};

Nützliche Helfer-Typen

Helfermacht aus einem Typ …
Partial<User>alle Eigenschaften optional (z. B. für Updates)
Required<User>alle Eigenschaften Pflicht
Readonly<User>alle Eigenschaften schreibgeschützt
Pick<User, "name" | "email">nur die genannten Eigenschaften
Omit<User, "age">alle außer den genannten
 
function updateUser(user: User, changes: Partial<User>): User {
  return { ...user, ...changes };
}

updateUser(user, { age: 31 });   // nur age ändern – ok

Tipps & typische Fehler

  • Interfaces gibt es nur beim Prüfen – if (x instanceof User) funktioniert nicht, weil User im JavaScript fehlt.
  • Daten aus fetch oder JSON.parse sind nicht automatisch geprüft. as User behauptet nur, dass es passt.
  • Zu viel Überschuss: Ein Objekt-Literal mit einer Eigenschaft, die das Interface nicht kennt, ist ein Fehler (oft ein Tippfehler).
