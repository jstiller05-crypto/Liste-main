Passwort-Sicherheit & Hashing

Ein gutes Passwort ist LANG und für jeden Dienst EINZIGARTIG – ein Passwort-Manager nimmt einem das Merken ab. Server speichern Passwörter dabei nie im Klartext, sondern als Hash (siehe Hash-Funktion im Verschlüsselungs-Teil des Spickers, konkret password_hash im PHP-Teil) – selbst bei einem Datenleck bleiben die echten Passwörter dadurch im besten Fall geschützt.

2FA

2FA (Zwei-Faktor-Authentifizierung) verlangt zusätzlich zum Passwort (etwas, das man WEISS) einen zweiten, unabhängigen Nachweis – etwas, das man HAT (z. B. ein Code aus einer App) oder etwas, das man IST (z. B. ein Fingerabdruck). Selbst ein gestohlenes Passwort allein reicht einem Angreifer dann nicht mehr.

Phishing

Phishing versucht, über gefälschte Nachrichten oder Webseiten an Zugangsdaten oder sensible Informationen zu kommen – meist, indem sich der Angreifer als vertrauenswürdige Quelle ausgibt (Bank, Chef, bekannter Dienst).

Malware

Malware ist der Oberbegriff für schädliche Software:

ArtBesonderheit
Virushängt sich an andere Programme an und verbreitet sich so weiter
Trojanertarnt sich als nützliche, harmlose Software
Ransomwareverschlüsselt Daten und erpresst Lösegeld fürs Entschlüsseln

Firewall

Eine Firewall kontrolliert Netzwerkverkehr nach festen Regeln und lässt nur erlaubte Verbindungen durch – als Software auf einem einzelnen Gerät oder als eigene Hardware zwischen Netzwerken.

Backup

Ein Backup ist eine regelmäßige Sicherheitskopie wichtiger Daten. Die bewährte 3-2-1-Regel:

3 Kopien der Daten insgesamt (Original + 2 Backups)
2 verschiedene Medienarten (z. B. interne Platte + externe SSD)
1 Kopie extern/offsite, räumlich getrennt vom Original
Die räumlich getrennte Kopie schützt gegen Fälle, die ALLE lokalen Kopien gleichzeitig treffen können – Diebstahl, Feuer oder eben auch Ransomware, die sämtliche erreichbaren Laufwerke verschlüsselt.

Tipps & typische Fehler

  • Ein „sicheres“ Passwort, das überall gleich wiederverwendet wird, ist nur so sicher wie der UNSICHERSTE Dienst, bei dem es jemals genutzt wurde.
  • Ein Backup, das man nie zum Wiederherstellen getestet hat, ist nur ein VERMUTETES Backup – regelmäßig testen gehört dazu.
  • Typische Angriffe auf eigene Webseiten/Programme wie SQL-Injection (Datenbank) oder XSS (Browser) stehen bereits bei SQL bzw. JavaScript im Spicker – hier geht es bewusst um die allgemeinen, sprachunabhängigen Grundlagen.
