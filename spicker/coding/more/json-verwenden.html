JSON · Verwenden

JSON verwenden

In jeder Sprache dasselbe Prinzip: JSON-Text ↔ eigene Datenstruktur, immer mit Fehlerbehandlung.

JavaScript

// JSON-Text -> JS-Wert
const text = '{"name":"Max","age":17}';
const data = JSON.parse(text);
console.log(data.name);              // "Max"

// JS-Wert -> JSON-Text
const obj = { name: "Anna", age: 16 };
const compact = JSON.stringify(obj);
console.log(compact);                // {"name":"Anna","age":16}

// mit Einrückung (3. Parameter = Leerzeichen pro Ebene) -> gut lesbar
const pretty = JSON.stringify(obj, null, 2);
console.log(pretty);
// {
//   "name": "Anna",
//   "age": 16
// }

// JSON.parse() wirft bei ungueltigem Text einen Fehler -> immer absichern
try {
  const result = JSON.parse('{ invalid json }');
  console.log(result);
} catch (error) {
  console.error("[json] Text konnte nicht gelesen werden:", error.message);
}

// Typischer Fall: JSON aus einer fetch-Antwort holen
fetch("/api/users")
  .then(response => response.json())  // parst die Antwort direkt als JSON
  .then(users => console.log(users))
  .catch(error => console.error("[json] fetch fehlgeschlagen:", error));

Node.js

const fs = require("fs");

// Datei lesen und als JSON interpretieren
try {
  const text = fs.readFileSync("daten.json", "utf8");
  const data = JSON.parse(text);
  console.log("[json] geladen:", data);
} catch (error) {
  // Greift sowohl bei fehlender Datei als auch bei kaputtem JSON
  console.error("[json] Lesen fehlgeschlagen:", error.message);
}

// JS-Wert als JSON-Datei speichern (eingerueckt, leichter lesbar)
const data = { name: "Max", points: 10 };
fs.writeFileSync("daten.json", JSON.stringify(data, null, 2), "utf8");
console.log("[json] gespeichert");

PHP

<?php
// JSON-Text -> PHP-Wert
$text = '{"name":"Max","age":17}';
$data = json_decode($text);
echo $data->name;              // "Max" (als Objekt)

// true als 2. Parameter -> assoziatives Array statt Objekt
$data = json_decode($text, true);
echo $data["name"];             // "Max" (als Array)

// PHP-Wert -> JSON-Text, lesbar formatiert
$obj = ["name" => "Anna", "age" => 16];
echo json_encode($obj, JSON_PRETTY_PRINT);

// Fehler abfangen: json_decode gibt bei ungueltigem JSON einfach null zurueck
$result = json_decode("{ invalid json }");
if ($result === null) {
    error_log("[json] Text konnte nicht gelesen werden");
}

Lua (Luanti)

In Luanti-Mods gibt es dafür fertige Engine-Funktionen – kein externes JSON-Modul nötig:

-- Lua-Tabelle -> JSON-Text
local tbl = { name = "Max", points = 10 }
local text = core.write_json(tbl)
print(text)                     -- {"name":"Max","points":10}

-- JSON-Text -> Lua-Tabelle
local decoded = core.parse_json('{"name":"Anna","age":16}')
if decoded then
    print(decoded.name)         -- "Anna"
else
    -- core.parse_json gibt bei ungueltigem JSON nil zurueck
    core.log("error", "[json] Text konnte nicht gelesen werden")
end

C++ (Qt)

#include <QFile>
#include <QJsonDocument>
#include <QJsonObject>
#include <QJsonArray>
#include <QDebug>

QFile file("daten.json");
if (!file.open(QIODevice::ReadOnly)) {
    qWarning() << "[json] Datei konnte nicht geoeffnet werden:" << file.errorString();
    return;
}

QJsonParseError parseError;
QJsonDocument doc = QJsonDocument::fromJson(file.readAll(), &parseError);

if (parseError.error != QJsonParseError::NoError) {
    // errorString() beschreibt genau, was und wo falsch ist
    qWarning() << "[json] Parser-Fehler:" << parseError.errorString();
    return;
}

QJsonObject obj = doc.object();
qDebug() << "name:" << obj["name"].toString();

QJsonArray items = obj["items"].toArray();
for (const QJsonValue& item : items) {
    qDebug() << item.toString();
}

Ohne Qt-Abhängigkeit ist nlohmann/json die verbreitetste Alternative – eine einzelne Header-Datei, die JSON fast wie eine normale C++-Datenstruktur behandelt.

Tipps & typische Fehler

  • Fehler beim Einlesen immer abfangen und loggen – in keiner der Sprachen oben stürzt das Programm dabei „automatisch“ kontrolliert ab.
  • JSON.stringify(obj, null, 2) bzw. JSON_PRETTY_PRINT nur für Menschen lesbar machen – für die Übertragung über eine API reicht die kompakte Form.
