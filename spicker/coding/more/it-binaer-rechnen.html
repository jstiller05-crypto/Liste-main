Binäre Addition

Binär addiert man genauso wie dezimal schriftlich – nur dass ein Übertrag schon ab einer Summe von 2 entsteht (nicht erst ab 10):

   0101   (5)
 + 0011   (3)
 ------
   1000   (8)

Stellenweise von rechts: 1+1=10 → 0 schreiben, 1 übertragen
                          0+1+Übertrag 1 = 10 → 0 schreiben, 1 übertragen
                          1+0+Übertrag 1 = 10 → 0 schreiben, 1 übertragen
                          0+0+Übertrag 1 = 1

Zweierkomplement

Das Zweierkomplement (two's complement) ist die Standard-Methode, um negative Zahlen binär darzustellen – fast jeder Prozessor rechnet intern so. Rezept: alle Bits invertieren (0↔1), dann 1 addieren.

  5 (8 Bit):  0000 0101
invertieren:   1111 1010
        + 1:   1111 1011   = −5 (im Zweierkomplement)
Der große Vorteil: Addition funktioniert mit positiven UND negativen Zahlen über dieselbe Schaltung, ohne Sonderfall für das Minuszeichen.

signed / unsigned

Bei unsigned (vorzeichenlos) stellen alle Bits den Betrag dar – nur Werte ≥ 0. Bei signed (mit Vorzeichen) ist das höchstwertige Bit (MSB) das Vorzeichenbit (Zweierkomplement): 0 = positiv, 1 = negativ. Dieselbe Bitbreite deckt dadurch bei signed einen anderen Bereich ab als bei unsigned:

8 BitWertebereich
unsigned0 bis 255
signed−128 bis 127

Überlauf (Overflow)

Ein Überlauf passiert, wenn das Rechenergebnis nicht mehr in die verfügbare Bitbreite passt.

#include <cstdint>

uint8_t a = 255;   // größter unsigned 8-Bit-Wert
a = a + 1;         // Überlauf: wird DEFINIERT zu 0 (wrap-around, 256 mod 256)

int8_t b = 127;    // größter signed 8-Bit-Wert
b = b + 1;         // Überlauf bei SIGNED ist in C++ UNDEFINIERTES Verhalten –
                    // in der Praxis meist (aber nicht garantiert!) −128
Wichtiger Unterschied: Überlauf bei unsigned ist in C++ klar definiert (Rechnen „modulo“ der Bitbreite). Überlauf bei signed ist undefiniertes Verhalten – der Compiler darf dabei theoretisch irgendetwas tun, auch wenn er in der Praxis meist einfach umklappt.

Bitoperatoren AND / OR / XOR / NOT

Bitoperatoren wenden eine logische Operation auf JEDES Bitpaar einzeln an – nicht auf die ganze Zahl als Wahrheitswert (das wäre &&/||, siehe unten).

ABAND (A & B)OR (A | B)XOR (A ^ B)

NOT (~A) kippt jedes einzelne Bit: aus 0 wird 1 und umgekehrt.

  1100
& 1010
------
  1000      (AND: nur dort 1, wo BEIDE 1 sind)

  1100
| 1010
------
  1110      (OR: dort 1, wo MINDESTENS EINES 1 ist)

  1100
^ 1010
------
  0110      (XOR: dort 1, wo sich die Bits UNTERSCHEIDEN)

In C++ und JavaScript sehen die Operatoren identisch aus: &, |, ^, ~.

Bitshift << >>

Ein Bitshift schiebt alle Bits um eine feste Anzahl Stellen nach links oder rechts – rechnerisch entspricht das einer Multiplikation bzw. Division durch eine Zweierpotenz.

0000 0011  (3)
<< 2     →  0000 1100  (12)   // 3 · 2² = 12

0000 1100  (12)
>> 2     →  0000 0011  (3)    // 12 ÷ 2² = 3 (abgerundet)
Bei NEGATIVEN signed-Zahlen ist >> in C++ implementierungsabhängig (meist ein arithmetischer Shift, der das Vorzeichenbit erhält). JavaScript unterscheidet das sogar explizit mit zwei Operatoren: >> (Vorzeichen bleibt erhalten) und >>> (füllt immer mit Nullen auf).

Boolesche Logik & Wahrheitstabelle

Die Bitoperatoren AND/OR/XOR/NOT von oben sind GENAU dieselbe Logik wie die boolesche Und/Oder/Nicht-Verknüpfung aus der Mathematik – nur dass hier jedes einzelne Bit einer Zahl als eigener Wahrheitswert behandelt wird, statt nur EIN true/false für die ganze Zahl. Die ausführliche Herleitung samt Wahrheitstabellen steht im Mathe-Teil dieses Spickers.

Tipps & typische Fehler

  • &/| (bitweise) NICHT mit &&/|| (logisch, auf ganze Wahrheitswerte) verwechseln – 2 & 1 ist 0, aber 2 && 1 ist true.
  • Signed Overflow in C++ ist undefiniertes Verhalten – sich beim Rechnen darauf zu verlassen, dass er „schon umklappt“, ist ein klassischer, schwer zu findender Bug.
  • Ein Linksshift kann selbst überlaufen, wenn die Bitbreite nicht reicht – << prüft das nicht automatisch.
