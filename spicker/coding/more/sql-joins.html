Beziehungen & JOIN

Tabellen über Fremdschlüssel verbinden und gemeinsam abfragen.

Warum mehrere Tabellen?

Statt den Namen eines Nutzers bei jeder Antwort erneut zu speichern, steht er einmal in users. Die Tabelle answers verweist nur über user_id darauf. Das spart Platz und verhindert Widersprüche.

Fremdschlüssel

CREATE TABLE users (
    id   INTEGER PRIMARY KEY,
    name TEXT NOT NULL
);

CREATE TABLE answers (
    id       INTEGER PRIMARY KEY,
    user_id  INTEGER NOT NULL,
    task     TEXT,
    correct  BOOLEAN,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

INNER JOIN – nur passende Paare

SELECT users.name, answers.task, answers.correct
FROM answers
INNER JOIN users ON answers.user_id = users.id;

-- kürzer mit Aliasen
SELECT u.name, a.task
FROM answers AS a
JOIN users   AS u ON a.user_id = u.id
WHERE a.correct = 1;

LEFT JOIN – alle links, auch ohne Partner

-- Alle Nutzer mit Anzahl ihrer Antworten – auch Nutzer ohne Antworten (dann 0)
SELECT u.name, COUNT(a.id) AS antworten
FROM users AS u
LEFT JOIN answers AS a ON a.user_id = u.id
GROUP BY u.id, u.name;

JOIN-Arten

JOINLiefert
INNER JOINNur Zeilen, die in beiden Tabellen einen Partner haben
LEFT JOINAlle Zeilen der linken Tabelle, rechts ggf. NULL
RIGHT JOINAlle Zeilen der rechten Tabelle (selten, lässt sich als LEFT JOIN schreiben)
FULL OUTER JOINAlle Zeilen beider Seiten (nicht in jeder Datenbank)

Tipps & typische Fehler

  • Bei mehreren Tabellen Spalten immer mit Tabellenname oder Alias angeben (u.name) – sonst gibt es Fehler bei gleichnamigen Spalten.
  • Vergessene ON-Bedingung erzeugt jede mögliche Kombination (kartesisches Produkt) – sehr viele Zeilen.
