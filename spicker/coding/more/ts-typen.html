TypeScript · Grundlagen

Grundtypen

Welche Typen es gibt, wie man sie schreibt – und wann TypeScript sie von allein errät.

Einfache Typen

let title: string = "Spicker";
let count: number = 42;          // ganze Zahlen UND Kommazahlen
let isOpen: boolean = true;
let nothing: null = null;
let notSet: undefined = undefined;

Die Typen werden klein geschrieben: string, nicht String.

Typen erraten lassen (Inferenz)

Weist du sofort einen Wert zu, erkennt TypeScript den Typ selbst. Die Angabe ist dann überflüssig.

let city = "Musterstadt";   // TS weiß: string
city = 5;                   // Fehler: number passt nicht zu string

const max = 10;             // Typ ist sogar genau 10 (weil const)
Faustregel: Bei Variablen mit Startwert den Typ weglassen, bei Funktions-Parametern immer angeben.

Arrays und Tupel

const scores: number[] = [3, 7, 9];
const names: Array<string> = ["Anna", "Ben"];   // gleiche Bedeutung

scores.push("zehn");   // Fehler: string ist keine number

// Tupel: feste Länge, feste Typen pro Position
const point: [number, number] = [10, 20];
const entry: [string, number] = ["Äpfel", 3];

Funktionen

// Parameter-Typen und Rückgabetyp
function add(a: number, b: number): number {
  return a + b;
}

// optionaler Parameter (?) und Standardwert
function greet(name: string, greeting?: string): string {
  return `${greeting ?? "Hallo"} ${name}`;
}

// Pfeilfunktion
const square = (x: number): number => x * x;

// void = gibt nichts zurück
function log(message: string): void {
  console.log("[log]", message);
}

Union-Typen: das eine ODER das andere

let id: number | string;
id = 17;        // ok
id = "A-17";    // ok
id = true;      // Fehler

function formatId(id: number | string): string {
  // Typ eingrenzen ("narrowing"): danach weiß TS genau, was id ist
  if (typeof id === "number") {
    return id.toFixed(0);       // hier ist id eine number
  }
  return id.toUpperCase();      // hier ist id ein string
}

Literal-Typen: nur ganz bestimmte Werte

let theme: "hell" | "dunkel" = "hell";
theme = "dunkel";   // ok
theme = "blau";     // Fehler

function move(direction: "oben" | "unten" | "links" | "rechts") {
  console.log("Bewege nach", direction);
}

any, unknown und never

TypBedeutungWann?
anySchaltet die Prüfung aus – alles ist erlaubtMöglichst nie; nur als Notlösung
unknownIrgendein Wert, aber erst prüfen, dann benutzenDaten von außen (JSON, API, Eingaben)
neverKann nie vorkommenFunktionen, die immer einen Fehler werfen
 
const data: unknown = JSON.parse('{"name":"Max"}');

// data.name;   // Fehler: erst prüfen!
if (typeof data === "object" && data !== null && "name" in data) {
  console.log(data.name);   // jetzt erlaubt
}

Typen einen Namen geben

type Id = number | string;
type Theme = "hell" | "dunkel";

let currentTheme: Theme = "hell";
function load(id: Id) { /* ... */ }

Für Objekte gibt es zusätzlich interface – mehr dazu auf der Seite „Interfaces & Objekttypen“.

Type Assertion (as)

// TS kennt nur "HTMLElement | null" – du weißt es besser
const input = document.getElementById("email") as HTMLInputElement;
console.log(input.value);

// Kurzform "!" = "ist sicher nicht null" (nur wenn du es wirklich weißt)
const button = document.querySelector("button")!;
as prüft nichts zur Laufzeit. Ist das Element doch nicht da, gibt es trotzdem einen Fehler im Browser.

Tipps & typische Fehler

  • number statt Number, string statt String – die Großbuchstaben-Varianten sind etwas anderes.
  • Lieber unknown als any: unknown zwingt dich zum Prüfen, any versteckt Fehler.
  • Mit typeof, in und Array.isArray() grenzt du Union-Typen ein – TS merkt sich das Ergebnis im jeweiligen if-Zweig.
