Git: Commits, Branches & GitHub

Wie Code-Änderungen nachvollziehbar werden – und wie der eigene Rechner mit GitHub zusammenspielt.

Git

Git ist ein verteiltes Versionskontrollsystem: Es verfolgt Änderungen am Code über die Zeit, erlaubt es, zu jedem früheren Stand zurückzukehren, und macht paralleles Arbeiten an verschiedenen Varianten möglich.

Repository

Ein Repository (kurz „Repo“) ist der Projektordner samt dem versteckten .git-Unterordner, in dem Git die komplette Änderungshistorie verwaltet.

Commit

Ein Commit ist ein gespeicherter Schnappschuss des Projekts zu einem bestimmten Zeitpunkt, zusammen mit einer Beschreibung (Commit-Message), was sich geändert hat und warum.

Branch

Ein Branch ist ein paralleler, unabhängiger Entwicklungsstrang. Änderungen auf einem Branch wirken sich zunächst NICHT auf andere Branches aus – bis man sie per Merge zusammenführt.

Merge

Ein Merge führt die Änderungen eines Branches wieder in einen anderen zusammen – zum Beispiel eine fertige Funktion zurück in den Hauptbranch.

push / pull

push lädt eigene, lokale Commits zu einem Remote-Repository hoch. pull macht das Umgekehrte: fremde Commits vom Remote herunterladen und mit dem eigenen Stand zusammenführen.

GitHub

GitHub ist ein Online-Dienst, der Git-Repositories hostet und zusätzliche Werkzeuge bietet – Pull Requests, Issues, Actions. Git selbst funktioniert komplett unabhängig davon; GitHub ist nur einer von mehreren möglichen Orten, ein Remote-Repository zu betreiben.

.gitignore

Die .gitignore-Datei legt fest, welche Dateien und Ordner Git bewusst NICHT verfolgen soll – typisch z. B. node_modules/ (lässt sich jederzeit neu installieren) oder eine .env-Datei mit Geheimnissen, die NIEMALS ins Repository gehört.

Tipps & typische Fehler

  • Ein Commit mit Message „fix“ oder „asdf“ hilft dem zukünftigen Ich nicht weiter – eine kurze, klare Beschreibung spart später viel Zeit.
  • Einmal gepushte Geheimnisse (Passwörter, API-Keys) in der Historie gelten als kompromittiert, selbst nach dem Löschen aus der aktuellen Datei – deshalb gehört Geheimes von Anfang an in .gitignore.
  • „git“ und „GitHub“ werden oft gleichgesetzt – Git ist die Technik, GitHub nur einer von mehreren Anbietern, die diese Technik online hosten.
