Port

Eine IP-Adresse identifiziert ein GERÄT im Netzwerk – ein Port (eine Zahl von 0 bis 65.535) identifiziert zusätzlich, für WELCHEN Dienst AUF diesem Gerät eine Nachricht bestimmt ist. Ein Server kann so gleichzeitig mehrere Dienste auf verschiedenen Ports anbieten, ohne dass sie sich in die Quere kommen.

Socket

Ein Socket ist die Kombination aus IP-Adresse UND Port, z. B. 192.168.1.20:443 – zusammen bezeichnet das eine ganz konkrete Verbindung zu einem bestimmten Dienst auf einem bestimmten Gerät.

3000 / 5173typische lokale Dev-Server (Node/Express bzw. Vite)
Ports unter 1024 gelten als „bekannte“ Ports für Standarddienste (HTTP, HTTPS, SSH …) – eigene Server und Entwicklungs-Tools nutzen deshalb meist höhere, freie Ports wie 3000.

localhost:3000

localhost:3000 heißt: Port 3000 auf dem eigenen Rechner (127.0.0.1). Genau das nutzt der Node-Server dieses Spickers (siehe server.js), und auch viele andere Entwicklungs-Server laufen standardmäßig auf einem solchen hohen Port – zum Beispiel Vite häufig auf Port 5173.

Tipps & typische Fehler

  • „Port schon belegt“ (EADDRINUSE) bedeutet meist: Ein anderer Prozess lauscht bereits auf genau diesem Port – entweder den alten Prozess beenden oder einen anderen Port wählen.
  • Fehlt die Portangabe in einer URL, wird automatisch der Standardport der jeweiligen Protokolls verwendet (80 bei HTTP, 443 bei HTTPS) – unsichtbar, aber trotzdem da.
  • Ein offener Port ist kein automatisches Sicherheitsrisiko an sich – entscheidend ist, WELCHER Dienst dahinter läuft und wie gut er abgesichert ist.
