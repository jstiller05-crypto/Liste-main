Header-Dateien & Projektaufbau

Code auf mehrere Dateien verteilen: .h für Deklarationen, .cpp für die Umsetzung.

Warum aufteilen?

Große Programme in einer einzigen main.cpp werden unübersichtlich. Üblich ist: pro Klasse bzw. Thema eine Header-Datei (.h/.hpp) mit der Deklaration und eine Quelldatei (.cpp) mit der Definition.

Beispiel

// MathUtils.h – WAS es gibt
#pragma once                       // verhindert doppeltes Einbinden

int add(int a, int b);
double average(const std::vector<int>& values);
// MathUtils.cpp – WIE es funktioniert
#include "MathUtils.h"
#include <vector>

int add(int a, int b) {
    return a + b;
}

double average(const std::vector<int>& values) {
    if (values.empty()) return 0.0;
    int sum = 0;
    for (int v : values) sum += v;
    return static_cast<double>(sum) / values.size();
}
// main.cpp
#include <iostream>
#include "MathUtils.h"             // eigene Header mit " ", Bibliotheken mit < >

int main() {
    std::cout << add(2, 3) << "\n";
    return 0;
}

Include Guards

// Variante 1 (modern, von allen großen Compilern unterstützt)
#pragma once

// Variante 2 (klassisch)
#ifndef MATHUTILS_H
#define MATHUTILS_H
// … Inhalt …
#endif

Tipps & typische Fehler

  • using namespace std; nie in Header-Dateien schreiben – es landet sonst in jeder Datei, die den Header einbindet.
  • Fehler „undefined reference to …“: Die .cpp-Datei wurde nicht mitkompiliert oder die Definition fehlt.
  • Fehler „multiple definition of …“: Eine Funktion wurde im Header definiert statt nur deklariert (oder inline fehlt).
