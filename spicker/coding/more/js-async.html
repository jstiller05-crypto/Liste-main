Timer, Promises & async/await

Code später oder regelmäßig ausführen und auf langsame Vorgänge wie das Laden von Daten warten.

Timer

// einmal nach 2 Sekunden
const timeoutId = setTimeout(() => {
  console.log("2 Sekunden vorbei");
}, 2000);

// alle 1000 ms
let seconds = 0;
const intervalId = setInterval(() => {
  seconds++;
  console.log(seconds);
  if (seconds === 5) clearInterval(intervalId);   // stoppen
}, 1000);

clearTimeout(timeoutId);   // geplanten Timeout abbrechen

Was ist asynchron?

Manche Dinge dauern: Daten aus dem Internet laden, eine Datei lesen, in die Zwischenablage kopieren. JavaScript wartet dabei nicht, sondern macht weiter. Das Ergebnis kommt später als Promise – ein „Versprechen“ auf einen Wert.

async / await

async function loadUsers() {
  try {
    const response = await fetch("https://example.com/api/users");   // warten auf Antwort
    if (!response.ok) {
      throw new Error("HTTP-Fehler " + response.status);
    }
    const users = await response.json();   // warten auf die Daten
    console.log(users);
  } catch (error) {
    console.error("Laden fehlgeschlagen:", error);
  }
}

loadUsers();

await geht nur in einer async-Funktion. Die Funktion pausiert an dieser Stelle, der Rest der Seite läuft weiter.

Dasselbe mit .then()

fetch("daten.json")
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error));

Eigene Verzögerung

const wait = ms => new Promise(resolve => setTimeout(resolve, ms));

async function countdown() {
  for (let i = 3; i > 0; i--) {
    console.log(i);
    await wait(1000);
  }
  console.log("Los!");
}

Tipps & typische Fehler

  • fetch funktioniert nicht, wenn die Seite direkt als Datei (file://) geöffnet ist – dafür einen lokalen Server nutzen (z. B. „Live Server“ in VS Code).
  • Immer Fehler behandeln (try/catch oder .catch) – Netzwerkanfragen können scheitern.
  • await vergessen? Dann bekommst du statt der Daten ein Promise {<pending>}.
