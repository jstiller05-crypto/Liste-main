Optionals

Werte, die fehlen dürfen – und wie Swift dadurch Abstürze durch nil verhindert.

Was ist das?

Ein normaler String hat immer einen Wert. Soll er fehlen dürfen, schreibt man String? – ein Optional. Bevor man ihn benutzt, muss man ihn „auspacken“. So erzwingt Swift, dass man an den Fall „kein Wert“ denkt.

Auspacken

let input = "42"
let number: Int? = Int(input)        // nil, wenn input keine Zahl ist

// 1) if let – nur wenn vorhanden
if let number {                       // Kurzform für: if let number = number
    print("Zahl: \(number)")
} else {
    print("Keine Zahl")
}

// 2) guard let – früh aussteigen
func double(_ text: String) -> Int {
    guard let value = Int(text) else {
        print("[Fehler] '\(text)' ist keine Zahl")
        return 0
    }
    return value * 2                  // ab hier ist value garantiert vorhanden
}

// 3) ?? – Ersatzwert
let safe = number ?? 0

// 4) ?. – Optional Chaining
let length = user?.name.count        // nil, wenn user nil ist

Die Varianten

SchreibweiseBedeutung
Type?Optional – Wert oder nil
if let x { }Nur ausführen, wenn Wert da ist
guard let x else { return }Aussteigen, wenn kein Wert – danach ist x sicher
x ?? standardErsatzwert
x?.eigenschaftNur zugreifen, wenn vorhanden
x!Erzwungenes Auspacken – Absturz, wenn nil

Tipps & typische Fehler

  • ! nur verwenden, wenn ein Wert garantiert da ist – sonst stürzt die App ab.
  • Das Konzept gibt es ähnlich in C# (string?), Kotlin und TypeScript.
