DNS, Domains & der Aufbau einer URL

Wie aus www.beispiel.de eine IP-Adresse wird, bevor der Browser überhaupt irgendetwas laden kann.

DNS

DNS (Domain Name System) übersetzt für Menschen lesbare Domainnamen wie beispiel.de in die IP-Adresse, die der Computer für die eigentliche Verbindung braucht – wie ein Telefonbuch des Internets.

Domain

Eine Domain ist nach dem Schema sub.domain.tld aufgebaut:

      www.beispiel.de
        │      │     │
        │      │     └─ TLD (Top-Level-Domain): .de, .com, .org …
        │      └─────── Domain: der eigentliche Name
        └────────────── Subdomain: oft "www", manchmal weggelassen

URL-Aufbau

Eine vollständige URL setzt sich aus mehreren Teilen zusammen:

https://www.beispiel.de:443/suche?q=katze#ergebnisse
└─┬──┘  └──────┬───────┘└┬┘└──┬──┘└───┬───┘└───┬────┘
Protokoll     Host      Port  Pfad   Query   Fragment
TeilBedeutung
Protokollhttps:// – wie verbunden wird
Hostdie Domain des Servers
Portoptional, oft weggelassen (dann Standardport)
Pfadwelche Seite/Ressource auf dem Server
QueryParameter nach ? – lesbar über URLSearchParams im Spicker
FragmentSprungmarke nach #, bleibt im Browser (geht nicht an den Server)

DHCP

DHCP (Dynamic Host Configuration Protocol) vergibt beim Verbinden mit einem Netzwerk automatisch eine passende IP-Adresse (und weitere Einstellungen wie den DNS-Server) an ein Gerät – ohne DHCP müsste man all das von Hand eintragen.

hosts-Datei

Die hosts-Datei ist eine lokale Textdatei auf jedem Rechner, in der man Domainnamen manuell fest einer IP-Adresse zuordnen kann. Sie wird VOR einer echten DNS-Anfrage geprüft – praktisch z. B., um eine Domain lokal zu Testzwecken auf den eigenen Rechner umzuleiten.

Tipps & typische Fehler

  • Nach einem DNS-Eintrags-Wechsel kann es eine Weile dauern, bis überall die neue IP ankommt – DNS-Antworten werden zwischengespeichert (Caching) und laufen erst nach einer Weile ab.
  • Das Fragment (#…) einer URL erreicht den Server NIE – es bleibt komplett im Browser.
  • Ein fehlerhafter hosts-Eintrag kann eine Domain dauerhaft „falsch“ auflösen lassen, selbst wenn DNS eigentlich korrekt wäre – ein klassischer, leicht übersehener Stolperstein.
