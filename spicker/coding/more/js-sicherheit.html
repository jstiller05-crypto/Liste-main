Sicherheit im Frontend

Die wichtigsten Regeln, damit deine Seite nicht zum Einfallstor wird – vor allem gegen XSS.

XSS – Cross-Site-Scripting

Gelangt fremder Text als HTML in die Seite, kann er <script> oder Event-Attribute enthalten – und dann läuft fremder Code mit allen Rechten deiner Seite (Cookies, Eingaben, Weiterleitungen).

const comment = '<img src="x" onerror="alert(\'gehackt\')">';   // z. B. aus einem Formular oder einer URL

element.innerHTML = comment;     // GEFÄHRLICH: onerror wird ausgeführt
element.textContent = comment;   // SICHER: wird als reiner Text angezeigt

URLs prüfen

function safeLink(url) {
  try {
    const parsed = new URL(url, location.href);
    return ["http:", "https:"].includes(parsed.protocol) ? parsed.href : "#";
  } catch {
    return "#";
  }
}

Weitere Regeln

  • Keine Geheimnisse im Frontend: API-Schlüssel, Passwörter und Admin-Logik kann jeder im Browser lesen (F12).
  • Nie nur im Browser prüfen: Jede Prüfung (Preise, Rechte, Eingaben) muss der Server wiederholen.
  • Links mit target="_blank" bekommen rel="noopener".
  • Fremde Skripte (CDNs, Tracking) nur von vertrauenswürdigen Quellen einbinden – sie haben volle Kontrolle über die Seite.
  • npm-Pakete prüfen und mit npm audit auf bekannte Lücken testen.
  • Content Security Policy (CSP) auf dem Server setzen – verbietet z. B. Inline-Skripte komplett.

Tipps & typische Fehler

  • Faustregel: Alles, was von außen kommt (Formular, URL, API, localStorage), ist unsicher, bis es geprüft ist.
  • Wer doch HTML von Nutzern anzeigen muss, verwendet eine Bibliothek wie DOMPurify zum Säubern.
