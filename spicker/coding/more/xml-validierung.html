XML-Validierung

Wohlgeformt reicht nicht immer – eine DTD oder ein XSD schreibt zusätzlich vor, welche Struktur ein Dokument haben MUSS.

Wohlgeformt vs. gültig

WohlgeformtGültig (valid)
Bedeutetfolgt den Grundregeln der XML-Syntaxfolgt ZUSÄTZLICH einer festgelegten Struktur (DTD/XSD)
Beispiel-Verstoßfehlender End-Tagein <book> ohne <title>, obwohl die Struktur es vorschreibt
Geprüft vonjedem XML-Parser automatischeinem Validator GEGEN die DTD/XSD

Jedes gültige Dokument ist automatisch wohlgeformt – umgekehrt nicht: Wohlgeformt ist nur die Mindestanforderung.

DTD (Document Type Definition)

Eine DTD beschreibt knapp, welche Elemente erlaubt sind und wie sie verschachtelt werden dürfen – für das library-Beispiel:

<!DOCTYPE library [
  <!ELEMENT library (book+)>         <!-- library enthält 1 oder mehr book -->
  <!ELEMENT book (title, author)>    <!-- jedes book: genau title, dann author -->
  <!ATTLIST book id CDATA #REQUIRED> <!-- book braucht ein Attribut "id" -->
  <!ELEMENT title (#PCDATA)>         <!-- title enthält nur Text -->
  <!ELEMENT author (#PCDATA)>        <!-- author enthält nur Text -->
]>

+ bedeutet „ein oder mehrmals“, #PCDATA steht für reinen Text, #REQUIRED macht ein Attribut zur Pflicht.

XSD (XML Schema)

Ein XSD beschreibt dasselbe, ist dabei aber selbst eine XML-Datei – und kennt echte Datentypen wie xs:string oder xs:integer:

<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="library">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="book" maxOccurs="unbounded">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="title" type="xs:string"/>
              <xs:element name="author" type="xs:string"/>
            </xs:sequence>
            <xs:attribute name="id" type="xs:integer" use="required"/>
          </xs:complexType>
        </xs:element>
      </xs:sequence>
    </xs:complexType>
  </xs:element>
</xs:schema>
DTDXSD
Eigene Syntaxja, eigenes Mini-Formatnein – selbst ganz normales XML
Datentypennein, nur Text/Strukturja (xs:string, xs:integer …)
Verbreitungälter, einfacherheute Standard für ernsthafte Validierung

Wie prüfen?

In VS Code die Erweiterung „XML“ von Red Hat installieren – sie zeigt Wohlgeformtheits- und (bei verknüpftem Schema) Validierungsfehler direkt im Editor an. Alternativ gibt es Online-Validatoren, bei denen man XML-Datei und DTD/XSD hochlädt.
