Lua in Luanti (Mods)

Grundaufbau eines Luanti-Mods: Ordner, mod.conf, init.lua und die wichtigsten API-Aufrufe.

Ordneraufbau

mods/
└── mymod/
    ├── mod.conf          -- Name, Beschreibung, Abhängigkeiten
    ├── init.lua          -- wird beim Start geladen
    └── textures/
        └── mymod_block.png
# mod.conf
name = mymod
description = Mein erster Mod
depends = default

Block registrieren

-- init.lua
core.register_node("mymod:magic_block", {
    description = "Magischer Block",
    tiles = { "mymod_block.png" },
    groups = { cracky = 3 },           -- mit Spitzhacke abbaubar
    light_source = 10,
})

core.log("action", "[mymod] geladen")   -- Ausgabe im Server-Log

Ältere Mods verwenden minetest. statt core. – beides funktioniert.

Rezept & Chat-Befehl

core.register_craft({
    output = "mymod:magic_block",
    recipe = {
        { "default:mese_crystal", "default:stone" },
        { "default:stone",        "default:mese_crystal" },
    }
})

core.register_chatcommand("hello", {
    description = "Sagt Hallo",
    func = function(name, param)
        return true, "Hallo " .. name .. "!"
    end,
})

Wichtige Funktionen

AufrufWofür
core.register_nodeNeuer Block
core.register_craftitem / register_toolGegenstand / Werkzeug
core.register_craftRezept
core.register_chatcommandChat-Befehl
core.register_on_joinplayerReagieren, wenn ein Spieler beitritt
core.register_globalstepCode bei jedem Server-Tick
core.get_node(pos) / core.set_node(pos, node)Block lesen / setzen
core.chat_send_player(name, text)Nachricht an einen Spieler
core.log(level, text)Ins Log schreiben

Tipps & typische Fehler

  • Luanti nutzt LuaJIT (Lua 5.1) – keine //-Division, kein <const>.
  • Namen immer mit Mod-Präfix: mymod:block, Texturen mymod_block.png.
  • Fehler stehen in debug.txt im Luanti-Ordner – nach dem Start von unten nach oben lesen.
