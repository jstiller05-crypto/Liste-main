XML · Syntax

XML-Syntax

Prolog, ein Wurzelelement, strenge Verschachtelung – und ein paar Sonderfälle für Zeichen, die XML selbst braucht.

Der Prolog

Die erste Zeile eines XML-Dokuments ist meist der Prolog – er nennt die XML-Version und die Zeichenkodierung:

<?xml version="1.0" encoding="UTF-8"?>

Er ist optional, aber übliche Praxis. Fehlt er, nehmen Parser UTF-8 als Standard an.

Das Wurzelelement

Ein XML-Dokument hat genau EIN äußerstes Element – das Wurzelelement. Alles andere steht darin verschachtelt:

✓ <library>...</library>                      (ein Wurzelelement)
✗ <book>...</book><book>...</book>              (zwei Elemente nebeneinander -> ungültig)

Elemente & Attribute

Ein Element hat einen Start- und End-Tag (<book>...</book>) oder, wenn es leer ist, einen selbstschließenden Tag: <item/>. Ein Attribut steht im Start-Tag und liefert eine Zusatzinfo:

<book id="1" lang="de">Clean Code</book>
<item/>                                 <!-- leeres Element -->

Groß-/Kleinschreibung zählt: <Book> und <book> sind zwei verschiedene Tags.

Element oder Attribut?Faustregel
Elementkann weitere Elemente oder Text enthalten, wenn die Information selbst noch Struktur hat
Attributfür kurze, einfache Zusatzinfos ohne eigene Struktur (eine ID, eine Sprache, ein Schalter)

Wohlgeformt

„Wohlgeformt“ heißt: Das Dokument folgt den Grundregeln der XML-Syntax (unabhängig davon, ob die Tag-Namen inhaltlich sinnvoll sind – das wäre die Gültigkeit).

  • Jedes Tag wird geschlossen (auch leere: <br/>, nicht <br> allein).
  • Elemente sind korrekt verschachtelt (kein Überlappen).
  • Attributwerte stehen in Anführungszeichen.
  • Es gibt genau ein Wurzelelement.
  • Groß-/Kleinschreibung ist case-sensitive.
FalschRichtig
<book>Text</Book><book>Text</book>
<b><i>Text</b></i><b><i>Text</i></b>
<book id=1><book id="1">

Entities

Manche Zeichen haben in XML eine Sonderbedeutung und müssen als Entity geschrieben werden, wenn sie als normaler Text gemeint sind:

ZeichenEntity
<&lt;
>&gt;
&&amp;
"&quot;
'&apos;

CDATA

Ein CDATA-Abschnitt markiert Text, der nicht als XML interpretiert werden soll – praktisch, wenn der Inhalt selbst viele </& enthält (z. B. Code-Beispiele):

<code><![CDATA[ if (a < b && b > 0) { ... } ]]></code>

Namespace (xmlns)

Ein Namespace hält gleich benannte Tags aus verschiedenen Formaten auseinander – ohne Namespace könnte z. B. ein <title> aus zwei unterschiedlichen XML-Formaten nicht unterschieden werden. Deklariert wird er über xmlns:

<svg xmlns="http://www.w3.org/2000/svg">
  <circle cx="50" cy="50" r="40" />
</svg>

Jedes SVG-Element gehört damit erkennbar zum SVG-Namespace, auch wenn es z. B. innerhalb einer HTML-Seite steht.
