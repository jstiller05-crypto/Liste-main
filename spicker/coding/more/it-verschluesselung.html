Verschlüsselung, Hashes & TLS

Ein Schlüssel oder zwei – und warum ein Hash etwas GANZ anderes ist als Verschlüsselung.

Verschlüsselung

Verschlüsselung wandelt Daten so um, dass sie nur mit dem passenden Schlüssel wieder lesbar (entschlüsselt) werden – ohne Schlüssel bleiben sie für Dritte unverständlich.

symmetrisch

Bei symmetrischer Verschlüsselung verwenden Sender und Empfänger DENSELBEN Schlüssel zum Ver- UND Entschlüsseln. Das ist schnell – aber beide Seiten müssen sich VORHER sicher auf diesen einen Schlüssel einigen, was bei einer ersten Verbindung über ein unsicheres Netz selbst zum Problem wird.

asymmetrisch

Bei asymmetrischer Verschlüsselung gehören IMMER zwei zusammenpassende Schlüssel zusammen: ein öffentlicher Public Key (den jeder kennen darf, zum Verschlüsseln) und ein geheimer Private Key (nur beim Empfänger, zum Entschlüsseln). Das löst das Schlüsselaustausch-Problem der symmetrischen Verschlüsselung – ist dafür aber deutlich langsamer.

Hash-Funktion (vs. Verschlüsselung!)

Eine Hash-Funktion wandelt beliebig große Daten in eine Prüfsumme fester Länge um – aber als EINWEG-Funktion: Es gibt KEINEN Weg zurück zu den Originaldaten, man kann nur prüfen, ob zwei Eingaben denselben Hash ergeben. Das ist der entscheidende Unterschied zur Verschlüsselung, die man mit dem richtigen Schlüssel absichtlich rückgängig machen kann. Genau deshalb werden Passwörter gehasht statt verschlüsselt (siehe password_hash im PHP-Teil des Spickers) – selbst der Server muss das Original-Passwort nie wieder im Klartext kennen.

TLS / SSL

TLS (Transport Layer Security) ist das Protokoll hinter HTTPS. SSL ist sein veralteter Vorgänger – umgangssprachlich wird „SSL“ aber bis heute oft für das aktuelle TLS verwendet. TLS kombiniert beide Welten geschickt: asymmetrische Verschlüsselung für den anfänglichen Schlüsselaustausch, danach schnellere symmetrische Verschlüsselung für die eigentlichen Daten.

Zertifikat

Ein Zertifikat bestätigt – digital signiert von einer vertrauenswürdigen Zertifizierungsstelle – dass ein bestimmter Public Key WIRKLICH zu einer bestimmten Domain gehört. Ohne diese Prüfung könnte sich jemand als der echte Server ausgeben und so Verschlüsselung vortäuschen, während er in Wahrheit mitliest.

Tipps & typische Fehler

  • „Verschlüsselt“ und „gehasht“ werden oft durcheinandergebracht – ein Hash lässt sich grundsätzlich NICHT entschlüsseln, auch nicht vom Betreiber selbst.
  • Ein Schloss-Symbol im Browser zeigt nur: Die Verbindung ist verschlüsselt. Es sagt NICHTS darüber aus, ob die Webseite selbst vertrauenswürdig ist.
  • Ein abgelaufenes oder falsches Zertifikat bedeutet nicht automatisch „gehackt“ – oft ist es einfach eine technische Nachlässigkeit des Betreibers.
