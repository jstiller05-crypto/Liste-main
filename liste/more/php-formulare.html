Formulare verarbeiten ($_GET, $_POST)

Eingaben aus HTML-Formularen empfangen, prüfen und sicher ausgeben.

Formular & Verarbeitung in einer Datei

<?php
$errors = [];
$name = "";

if ($_SERVER["REQUEST_METHOD"] === "POST") {          // wurde abgeschickt?
    $name  = trim($_POST["name"] ?? "");
    $email = trim($_POST["email"] ?? "");

    if ($name === "") {
        $errors[] = "Bitte einen Namen eingeben.";
    }
    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        $errors[] = "Die E-Mail-Adresse ist ungültig.";
    }

    if (!$errors) {
        // … speichern, E-Mail senden …
        header("Location: danke.php");               // weiterleiten (verhindert doppeltes Absenden)
        exit;
    }
}
?>
<form method="post">
  <?php foreach ($errors as $error): ?>
    <p class="error"><?= htmlspecialchars($error) ?></p>
  <?php endforeach; ?>

  <label>Name <input name="name" value="<?= htmlspecialchars($name) ?>"></label>
  <label>E-Mail <input name="email" type="email"></label>
  <button type="submit">Senden</button>
</form>

Superglobale Variablen

VariableEnthält
$_GETWerte aus der URL: seite.php?page=2 → $_GET["page"]
$_POSTWerte aus einem Formular mit method="post"
$_SERVERInfos zur Anfrage, z. B. REQUEST_METHOD
$_FILESHochgeladene Dateien
$_SESSION / $_COOKIESitzungs- und Cookie-Daten

Die Schlüssel entsprechen dem name-Attribut der Formularfelder.

Sicher ausgeben: htmlspecialchars

echo $_GET["name"];                       // GEFÄHRLICH
echo htmlspecialchars($_GET["name"]);     // sicher: < wird zu &lt; usw.

Ohne htmlspecialchars kann jemand <script>-Code eingeben, der dann bei anderen Besuchern ausgeführt wird (Cross-Site-Scripting, XSS).

Tipps & typische Fehler

  • Jede Nutzereingabe ist verdächtig: prüfen beim Empfangen, htmlspecialchars beim Ausgeben, Platzhalter beim Speichern in der Datenbank.
  • ?? "" verhindert Warnungen, wenn ein Feld fehlt.
  • Nach erfolgreichem POST weiterleiten (Post/Redirect/Get) – sonst sendet F5 das Formular erneut.
