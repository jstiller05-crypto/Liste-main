SQL-Injection & Prepared Statements

Die gefährlichste Sicherheitslücke bei Datenbanken – und wie man sie zuverlässig verhindert.

Das Problem

// FALSCH – Eingabe wird direkt in den SQL-Text eingebaut
const sql = "SELECT * FROM users WHERE name = '" + input + "'";

Gibt jemand statt eines Namens ' OR '1'='1 ein, entsteht:

SELECT * FROM users WHERE name = '' OR '1'='1'   -- trifft ALLE Nutzer

So können Angreifer fremde Daten lesen, ändern oder ganze Tabellen löschen.

Die Lösung: Platzhalter

Der SQL-Text und die Werte werden getrennt an die Datenbank geschickt. Die Datenbank behandelt die Werte dann immer als Daten, nie als SQL-Befehl.

// Node.js
db.prepare("SELECT * FROM users WHERE name = ?").get(input);
// PHP (PDO)
$stmt = $pdo->prepare("SELECT * FROM users WHERE name = :name");
$stmt->execute(["name" => $input]);

Weitere Regeln

  • Passwörter nie im Klartext speichern – immer gehasht (password_hash in PHP, bcrypt in Node).
  • Den Datenbank-Benutzer der Anwendung nur mit den nötigen Rechten ausstatten (kein Admin).
  • Zugangsdaten nicht in den Code schreiben, sondern in eine .env-Datei.
  • Regelmäßige Backups.

Tipps & typische Fehler

  • Platzhalter funktionieren nur für Werte. Spalten- oder Tabellennamen (z. B. für eine Sortierung) gegen eine feste Liste erlaubter Namen prüfen.
  • Eingaben zusätzlich prüfen (Länge, Format) – das ersetzt Platzhalter aber nicht.
