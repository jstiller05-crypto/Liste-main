Kompilieren & Build

Wie aus .cpp-Dateien ein Programm wird – mit g++, Compiler-Warnungen und CMake.

Vom Code zum Programm

main.cpp ──┐
           ├─► Präprozessor (#include, #define)
           ├─► Compiler  → main.o   (Maschinencode je Datei)
utils.cpp ─┘              utils.o
                             │
                             ▼
                          Linker  → programm.exe

Mit g++ auf der Kommandozeile

# eine Datei
g++ main.cpp -o programm

# mehrere Dateien, moderner Standard, Warnungen an
g++ -std=c++17 -Wall -Wextra main.cpp utils.cpp -o programm

# ausführen
./programm          # Linux
.\programm.exe      # Windows (PowerShell)
OptionBedeutung
-o nameName der fertigen Programmdatei
-std=c++17 / -std=c++20C++-Version
-Wall -WextraViele nützliche Warnungen einschalten
-gDebug-Informationen (für den Debugger)
-O2Optimieren (schnelleres Programm)
-I includeZusätzlicher Ordner für Header

CMake

Bei mehreren Dateien schreibt man die Befehle nicht mehr von Hand, sondern beschreibt das Projekt in einer CMakeLists.txt. IDEs wie VS Code, CLion oder Qt Creator lesen diese Datei direkt.

cmake_minimum_required(VERSION 3.16)
project(MeinProjekt LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

add_executable(MeinProjekt
    src/main.cpp
    src/Player.cpp
)

target_include_directories(MeinProjekt PRIVATE include)
# bauen
cmake -S . -B build
cmake --build build

Tipps & typische Fehler

  • Warnungen ernst nehmen – sie zeigen oft echte Fehler.
  • Nach Änderungen an CMakeLists.txt das Projekt neu konfigurieren.
  • Linux-Test: Viele Unterschiede zwischen Windows und Linux zeigen sich erst beim Kompilieren mit einem anderen Compiler (MSVC vs. GCC) – früh auf beiden testen.
