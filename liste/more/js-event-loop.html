Event Loop

Wie JavaScript mit nur einem Thread trotzdem auf Klicks, Timer und Netzwerk reagiert.

Das Grundprinzip

JavaScript führt Code in einem Thread aus – immer nur eine Sache gleichzeitig. Langsame Dinge (Timer, fetch, Klicks) erledigt der Browser nebenher und legt die fertigen Callbacks in Warteschlangen. Die Event Loop holt sie heraus, sobald der aktuelle Code fertig ist.

┌─────────────────┐
│   Call Stack    │  ← läuft gerade (immer nur eins)
└────────┬────────┘
         │ leer?
         ▼
┌─────────────────┐   zuerst ALLE
│ Microtask-Queue │   Promise.then, await-Fortsetzungen
└────────┬────────┘
         ▼
┌─────────────────┐   dann EINE
│   Task-Queue    │   setTimeout, Klicks, Events
└────────┬────────┘
         ▼
     Neu zeichnen → von vorn

Welche Reihenfolge?

console.log("1: synchron");

setTimeout(() => console.log("4: setTimeout (Task)"), 0);

Promise.resolve().then(() => console.log("3: Promise (Microtask)"));

console.log("2: synchron");

// Ausgabe: 1, 2, 3, 4

setTimeout(…, 0) heißt nicht „sofort“, sondern „so bald wie möglich, nachdem alles andere fertig ist“.

Warum die Seite einfriert

button.addEventListener("click", () => {
  const end = Date.now() + 3000;
  while (Date.now() < end) {}     // 3 Sekunden Dauerschleife blockiert ALLES:
});                               // keine Klicks, kein Scrollen, kein Neuzeichnen

Lange Berechnungen deshalb aufteilen oder in einen Web Worker auslagern – der läuft in einem eigenen Thread.

Tipps & typische Fehler

  • await pausiert nur die aktuelle async-Funktion, nicht die ganze Seite.
  • Ein Tab, der „nicht reagiert“, hängt fast immer in einer langen synchronen Schleife.
