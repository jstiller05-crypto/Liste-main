tsconfig & Projekt einrichten

Die Datei tsconfig.json steuert, wie streng TypeScript prüft und wohin die JavaScript-Dateien geschrieben werden.

Ordnerstruktur

mein-projekt/
├─ src/
│  └─ main.ts          ← hier schreibst du
├─ dist/               ← hier landet das fertige JavaScript
├─ index.html          ← bindet dist/main.js ein
├─ package.json
└─ tsconfig.json

Eine einfache tsconfig.json

{
  "compilerOptions": {
    "target": "ES2022",         // welche JS-Version erzeugt wird
    "module": "ES2022",         // import/export bleiben erhalten
    "lib": ["ES2022", "DOM"],   // DOM = document, window usw. sind bekannt
    "rootDir": "src",           // Quelle
    "outDir": "dist",           // Ausgabe
    "strict": true,             // alle strengen Prüfungen an (empfohlen)
    "sourceMap": true           // Fehler im Browser zeigen auf die .ts-Zeile
  },
  "include": ["src"]
}

Wichtige Optionen

OptionBedeutung
strictSchaltet viele Prüfungen gleichzeitig an, z. B. strictNullChecks (null muss beachtet werden)
noImplicitAnyFehler, wenn TS keinen Typ erkennen kann (in strict enthalten)
targetJS-Version der Ausgabe – für moderne Browser ES2022
outDir / rootDirWo die .js-Dateien landen / wo die .ts-Dateien liegen
noEmitNur prüfen, keine Dateien schreiben (wenn Vite übersetzt)
allowJsAuch .js-Dateien im Projekt erlauben – gut zum schrittweisen Umstieg

Skripte in package.json

{
  "scripts": {
    "build": "tsc",
    "watch": "tsc --watch",
    "check": "tsc --noEmit"
  }
}
npm run build     # einmal übersetzen
npm run watch     # dauerhaft beobachten
npm run check     # nur Typfehler suchen

Im HTML einbinden

<!-- das übersetzte JavaScript, nicht die .ts-Datei -->
<script type="module" src="dist/main.js"></script>

Mit Node.js benutzen

# Typen für Node.js-Funktionen (fs, path, process …)
npm install -D @types/node

# .ts direkt ausführen, ohne vorher zu übersetzen
npx tsx src/main.ts

Pakete ohne eigene Typen bekommen sie oft über @types/paketname. Viele moderne Pakete bringen ihre Typen schon mit.

Bestehendes JS schrittweise umstellen

  1. allowJs einschalten, damit alte und neue Dateien nebeneinander funktionieren.
  2. Eine Datei nach der anderen von .js in .ts umbenennen.
  3. Die rot markierten Stellen reparieren – meist fehlen nur Parameter-Typen.
  4. Wenn alles läuft: strict einschalten und die restlichen Meldungen abarbeiten.

Tipps & typische Fehler

  • strict: true von Anfang an – später einschalten bedeutet viele Fehler auf einmal.
  • Den Ordner dist/ nicht von Hand bearbeiten, er wird bei jedem Build überschrieben.
  • Wenn document unbekannt ist, fehlt "DOM" in lib.
