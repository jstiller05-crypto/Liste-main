Sessions & Cookies

Daten über mehrere Seitenaufrufe hinweg merken – z. B. für Logins oder Warenkörbe.

Sessions

<?php
session_start();                        // GANZ OBEN, vor jeder Ausgabe

$_SESSION["user"] = "Max";              // speichern
$_SESSION["visits"] = ($_SESSION["visits"] ?? 0) + 1;

echo "Hallo {$_SESSION['user']}, Besuch Nr. {$_SESSION['visits']}";

// Abmelden
session_unset();
session_destroy();

Die Daten liegen auf dem Server. Der Browser bekommt nur eine zufällige Session-ID als Cookie.

Einfacher Login-Schutz

<?php
// geschützte Seite
session_start();
if (!isset($_SESSION["user_id"])) {
    header("Location: login.php");
    exit;
}
<?php
// login.php (Ausschnitt)
if (password_verify($_POST["password"], $userFromDb["password_hash"])) {
    session_regenerate_id(true);        // neue Session-ID gegen Session-Diebstahl
    $_SESSION["user_id"] = $userFromDb["id"];
}

Cookies

setcookie("theme", "dark", [
    "expires"  => time() + 60 * 60 * 24 * 30,   // 30 Tage
    "path"     => "/",
    "httponly" => true,                         // nicht per JavaScript lesbar
    "samesite" => "Lax"
]);

$theme = $_COOKIE["theme"] ?? "light";

Tipps & typische Fehler

  • session_start() und setcookie() müssen vor jeder HTML-Ausgabe stehen – sonst „headers already sent“.
  • Passwörter mit password_hash() speichern und mit password_verify() prüfen – nie im Klartext.
  • Keine sensiblen Daten in Cookies ablegen.
