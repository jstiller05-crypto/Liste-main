Speicher: new/delete & Smart Pointer

Stack und Heap verstehen – und warum man heute Smart Pointer statt new/delete nutzt.

Stack und Heap

StackHeap
AnlegenPlayer p;new Player() / std::make_unique<Player>()
FreigebenAutomatisch am Ende des BlocksManuell (delete) oder durch Smart Pointer
GrößeKlein (wenige MB)Groß
Gut fürNormale lokale VariablenGroße Daten, Objekte mit unbestimmter Lebensdauer, Polymorphie

new & delete (alt, fehleranfällig)

Player* p = new Player("Max");   // auf dem Heap anlegen
p->addScore(10);                 // -> für Zugriff über Zeiger
delete p;                        // Speicher freigeben – vergessen = Speicherleck

int* numbers = new int[100];
delete[] numbers;                // bei Arrays delete[]

Smart Pointer (modern)

#include <memory>

// unique_ptr: genau ein Besitzer, gibt automatisch frei
std::unique_ptr<Player> player = std::make_unique<Player>("Max");
player->addScore(10);
// kein delete nötig – Freigabe am Ende des Blocks

// Besitz weitergeben
std::unique_ptr<Player> other = std::move(player);   // player ist jetzt leer

// shared_ptr: mehrere Besitzer, frei wenn der letzte weg ist
std::shared_ptr<Player> a = std::make_shared<Player>("Anna");
std::shared_ptr<Player> b = a;          // beide zeigen auf dasselbe Objekt
std::cout << a.use_count() << "\n";    // 2
Smart PointerWann?
std::unique_ptrStandardfall – ein klarer Besitzer
std::shared_ptrMehrere Stellen teilen sich ein Objekt
std::weak_ptrBeobachten ohne zu besitzen (gegen Zyklen)

Typische Speicherfehler

FehlerFolge
delete vergessenSpeicherleck – Programm braucht immer mehr RAM

Zugriff nach delete„Dangling Pointer“ – liest Müll oder stürzt ab
nullptr dereferenzierenAbsturz (Segmentation fault)

Tipps & typische Fehler

  • Faustregel: Kein new/delete im eigenen Code – std::make_unique und Container wie std::vector erledigen das.
  • Vor Zugriff über einen Zeiger prüfen: if (ptr) { … }.
  • In Qt übernimmt oft das Eltern-Objekt die Freigabe (new QLabel(parent)) – dort ist new ohne delete üblich.
