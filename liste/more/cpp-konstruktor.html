Konstruktor, Destruktor & Kapselung

Wie Objekte entstehen und aufgeräumt werden – und wie man Daten mit private schützt.

Konstruktor mit Initialisierungsliste

class Player {
public:
    // Konstruktor: gleicher Name wie die Klasse, kein Rückgabetyp
    Player(const std::string& name, int level)
        : name(name), level(level), score(0)    // Initialisierungsliste
    {
        std::cout << "[Player] " << name << " erstellt\n";
    }

    // Standard-Konstruktor
    Player() : Player("Unbekannt", 1) {}          // ruft den anderen auf

    // Destruktor: wird automatisch aufgerufen, wenn das Objekt verschwindet
    ~Player() {
        std::cout << "[Player] " << name << " entfernt\n";
    }

private:
    std::string name;
    int level;
    int score;
};

int main() {
    Player p1("Max", 3);
    Player p2;
    return 0;
}   // hier laufen die Destruktoren (erst p2, dann p1)

Kapselung: public, private, protected

ZugriffWer darf zugreifen?
publicAlle
privateNur die Klasse selbst (Standard bei class)
protectedDie Klasse und abgeleitete Klassen
 
class BankAccount {
public:
    void deposit(double amount) {
        if (amount <= 0) {
            std::cerr << "[BankAccount] Ungültiger Betrag\n";
            return;
        }
        balance += amount;
    }

    double getBalance() const {   // Getter
        return balance;
    }

private:
    double balance = 0.0;         // von außen nicht direkt änderbar
};

Der Vorteil: Die Klasse kontrolliert, wie ihre Daten geändert werden – negative Einzahlungen sind unmöglich.

Klasse auf Header und Quelldatei aufteilen

// Player.h
#pragma once
#include <string>

class Player {
public:
    Player(const std::string& name);
    void addScore(int points);
    int getScore() const;
private:
    std::string name;
    int score = 0;
};
// Player.cpp
#include "Player.h"

Player::Player(const std::string& name) : name(name) {}

void Player::addScore(int points) {
    score += points;
}

int Player::getScore() const {
    return score;
}

Tipps & typische Fehler

  • Initialisierungsliste statt Zuweisung im Rumpf – schneller und für const-Member Pflicht.
  • Einen Konstruktor mit einem Parameter mit explicit markieren, um versehentliche Umwandlungen zu verhindern.
  • Einen eigenen Destruktor braucht man meist nur, wenn die Klasse selbst Speicher mit new verwaltet – mit Smart Pointern fast nie.
